ASCO 2026 abstract evidence review app

Operator guide for reviewing, filtering, and triaging ASCO abstract evidence

This guide describes the static evidence review interface built for ASCO 2026 abstracts. The app is intended to support structured review of abstracts by session type, ASCO conference track, keyword search, and heuristic role categories. It is a triage surface, not a source of adjudicated scientific claims.

01 Start with corpus orientation

Use the overview to understand coverage before filtering

The overview panel provides the first quality check for the abstract corpus. Review the total number of abstracts, session type distribution, role distribution, and track mix before selecting filters. This establishes whether the question should be answered from the full corpus or a narrower subset.

Overview metrics

Use the metric tiles to confirm the size of the current evidence set and the number of abstracts remaining after filters are applied. Counts update with the active filter state.

Session type distribution

Session type is the ASCO presentation or session format field. It supports quick distinction between presentation formats and Publication Only records.

Conference tracks

Conference track is the ASCO track or topic grouping from the abstract record. It is used as a full-corpus filter, independent of role tags.

Role categories

Role labels are heuristic triage aids derived from abstract text and metadata. They should help prioritize review, not replace source-level interpretation.

Publication Only definition

Publication Only means accepted abstracts published online or in meeting materials but not assigned to poster, oral, rapid oral, clinical science symposium, or plenary presentation slots. Other session type rows are ASCO-assigned presentation formats.

Annotated callout boxes identify summary counts, role controls, session type distribution, conference tracks, and the active abstract list.

02 Understand categorization fields

Separate ASCO source fields from heuristic triage fields

The app combines source metadata from ASCO abstract records with derived role categories. Treat ASCO fields as record metadata and role categories as keyword-based review aids. The distinction is important when citing evidence, preparing source notes, or checking whether an abstract belongs in a functional workstream.

Callout boxes highlight where session type distribution appears and how it supports format-aware review.

Field
Meaning
How to use it
Session type
ASCO presentation or session format field. Publication Only records are accepted abstracts published online or in meeting materials without an assigned poster, oral, rapid oral, clinical science symposium, or plenary presentation slot.
Use for format-aware review, for example prioritizing oral sessions while still retaining Publication Only records for evidence surveillance.
Conference track
ASCO track or topic grouping from the abstract record. It reflects the source record grouping, not a custom taxonomy.
Use as a full-corpus filter to constrain review to disease areas, modalities, methods, or meeting topic groups.
Role category
Heuristic keyword-based triage category derived from title, body, track, and abstract number, with track boosts. Records can have multiple role tags.
Use to route abstracts to Medical Affairs, HEOR, Market Access, Commercial, or Launch review. Verify claims against the ASCO source URL.
Primary role
The role with the highest keyword-hit count. If no role is classified, records can default to Medical Affairs for conservative clinical review.
Use for the first-pass list order or owner assignment. Do not treat it as manual adjudication.
Interpretation rule

Scores, chips, and tags are triage aids. They indicate why a record was surfaced for a workstream, but any scientific or competitive claim should be checked against the abstract detail and the linked ASCO source page.

04 Combine filters with AND logic

Role, track, and search filters narrow the same working set

Filters are combined using AND logic. If a role and conference track are both selected, the list shows only abstracts matching both criteria. Adding a search term further restricts the current set to records containing the term in indexed text fields.

Role plus track

Use this when a functional question is tied to an ASCO topic area, such as Market Access signals within a specific disease or methods track.

Full-corpus track filter

Track filters operate across the entire abstract corpus. They are not dependent on role assignment and can be used alone for topic-based scanning.

Callout boxes show how the filtered count reflects the intersection of active role, conference track, and any search terms.

05 Search the abstract text

Use search for endpoint, population, intervention, and comparator terms

The search field supports targeted review within the active filter state. It is useful for endpoint terms such as overall survival, progression-free survival, response rate, adverse events, quality of life, cost, and biomarker-defined subgroups.

Callout boxes identify the search term and the resulting active list of abstracts containing "overall survival" in indexed fields.

Search practice

Use multiple narrow searches rather than one broad query when reviewing endpoint-specific evidence. For example, search "overall survival", then "quality of life", then a competitor name, while preserving the same role and track filters.

06 / 08
06 Review selected abstract detail

Use the detail pane as the source-checking workspace

Selecting an abstract opens a structured detail view. Use this pane to read the title, body sections, track metadata, session type, speaker or presenter metadata where available, role chips, keyword tags, and source link. The list is for navigation; the detail pane is for interpretation.

Callout boxes identify source metadata, structured abstract text, role chips, tags, and the View on ASCO source link.

Structured sections

Review background, methods, results, conclusions, and available metadata as separate fields when the source record provides them.

Chips and tags

Use chips to understand why a record was triaged to a role. Treat them as prompts for review, not final labels.

ASCO source link

Use View on ASCO source before citing or summarizing a claim outside the app.

Methods statement

Role categories are heuristic keyword-based triage categories derived from abstract title, body, track, and abstract number with track boosts. Records can have multiple roles. The primary role is the highest keyword-hit count. Unclassified records can default to Medical Affairs. Scores and tags are triage aids, and claims should be checked against the ASCO source URL.
