# Cohere-Style CI Skill Feedback

Applicable: yes.

For viewer-facing competitive intelligence reports, the cohere-style-ci skill should emphasize that visible report text should describe conference/source data, records, retained and excluded candidates, source URLs, and relevant metadata. It should avoid references to local files, local archives, generated inventories, analyst-run artifacts, source hashes, run manifests, JSON/MD archive material, saved records, source-log wording, and analysis process language.

This is a generalizable reporting-quality rule for CI outputs: distinguish viewer-facing evidence and metadata from internal generation, audit, and archive artifacts.

When annotated feedback calls for bold headings in CI reports, scope bolding to section, card, and panel headings. Body paragraphs, table body text, list items, source notes, citations, and other non-chip reading text should remain regular or medium weight for readability and hierarchy discipline. Chips and tags may remain bold.

For title hierarchy in future cohere-style-ci competitive-intelligence reports, keep main slide h1 and h2 titles regular or medium weight. Reserve bold weight for h3 section/card/panel headings and for chips/tags so the hierarchy stays clear without over-weighting slide titles.

The shared cohere-style-ci skill itself was not edited because current task ownership is limited to outputs\endo_2026_ai_topics_ci.
