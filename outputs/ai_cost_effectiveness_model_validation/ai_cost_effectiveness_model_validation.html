Validation map 02 / 07

Turn an opaque workbook into a bounded review surface

Workbook structure

  • Identify input, calculation, DSA, PSA, and summary sheets
  • Map named ranges, protected tabs, and key output cells
  • Separate editable assumptions from generated results

Formula integrity

  • Scan for broken references, deleted anchors, and hardcodes
  • Trace dependent output cells back to assumptions
  • Compare repeated formulas across row and column blocks

Model behavior

  • Stress test boundary values and unlikely combinations
  • Check monotonicity for cost, utility, and risk drivers
  • Validate deterministic and probabilistic result coherence

Audit trail

  • Classify findings by severity, evidence, and reproducibility
  • Record questions that require human model owner judgment
  • Keep recommendations separate from implemented fixes

Prompt playbook 04 / 07

Accuracy validation starts with explicit invariants

Recalculate targets

  • Ask for independent recomputation of headline costs, QALYs, ICERs, and net monetary benefit
  • Require a source cell and dependency path for every number cited

Check formula families

  • Compare adjacent formulas across model blocks
  • Flag formulas that break row, column, or scenario patterns

Verify assumptions

  • Separate clinical inputs, utilities, costs, discounting, and cycle logic
  • List assumptions that are missing units or provenance

Reusable prompt

Audit this cost effectiveness workbook for calculation accuracy. First map the sheets and key outputs. Then independently recompute the base-case ICER and probabilistic summary from source inputs where possible. For every discrepancy, return the cell, formula, expected behavior, observed behavior, and whether it is confirmed or requires human interpretation.

Why it works: the prompt asks the AI to show provenance and separate confirmed arithmetic issues from judgment calls. That makes the output reviewable instead of merely plausible.

Accuracy checks need traceable evidence Do not accept uncited numeric conclusions
Prompt playbook 05 / 07

Edge cases test whether the model behaves clinically

Reusable prompt

Stress test the model with edge-case assumptions without editing the workbook. Propose boundary scenarios for treatment cost, comparator cost, discontinuation, mortality, adverse events, utilities, and discount rates. For each scenario, state the expected direction of change and the output cells that should move.

The goal is not to invent clinical evidence. The goal is to verify that model mechanics respond in the direction a health economist would expect.

Dominance and extended dominance

  • Check whether rankings change plausibly as incremental costs and effects cross zero

Zero and extreme costs

  • Confirm cost drivers never create impossible negative totals unless explicitly modeled

Utility bounds

  • Verify utilities remain interpretable and QALYs stay consistent with cycle length

PSA stability

  • Check whether simulation outputs collapse to errors, blanks, or nonrandom duplicates
Boundary tests expose silent spreadsheet logic failures Clinical plausibility remains a human review step
Prompt playbook 06 / 07

Error triage turns AI output into a worklist

Reusable prompt

Convert the audit findings into a triage table with severity, affected outputs, reproducibility, root-cause hypothesis, confidence, and recommended next action. Separate confirmed formula errors from missing source data, clinical assumptions, and fixes that require model owner approval.

In the observed workflow, Claude identified real workbook defects, including deleted anchor cells affecting DSA formulas and a downstream PSA issue. It also asked whether to fix formulas, which is where the validation-only boundary matters.

Findings become decisions only after ownership is assigned Report first, modify later
Audit trail 07 / 07

Human signoff is the control point

Workbook not changed

Claude asked whether to fix the formulas, but the workflow intentionally stopped at validation. The report preserves the evidence trail and requires the model owner to approve any formula edit.

Signoff checklist

  • Confirm each finding against the workbook and source specification
  • Classify whether the issue changes base-case or scenario conclusions
  • Document accepted fixes, rejected fixes, and unresolved questions
  • Version the corrected workbook separately from the validation report
  • Rerun deterministic, DSA, and PSA outputs after approved edits
